## 상태 목록

- 장바구니 **비었을 때** / 담겼을 때 / 수량 조절 / 삭제
- 검색·필터 결과 **0건**
- 제품 **품절** 배지
- 캐러셀 첫 장 / 끝 장 (원본은 순환)
- 탭 전환 시 카드 개수는 유지된다 (노드 증감 0)

## 범위 판정 — 왜 이렇게 잘랐나

**만든다:** 홈 · GNB 드롭다운 · 카테고리 목록 · 제품 상세 · 장바구니 · 검색 결과.
이 여섯이면 커머스의 성격이 다 드러난다. 목록에서 상세로 가고 담아서 장바구니를 여는 것이 핵심 동선이다.

**안 만든다:** 구독·케어(72링크로 가장 크지만 별도 서비스에 가깝다) · 스토리(콘텐츠 사이트).
범위를 넓히면 끝이 없고, 이 둘은 홈의 성격을 설명하는 데 필요하지 않다.

**절대 안 만든다:** 로그인 · 결제 · 주문조회.
자격증명이나 결제 정보를 받는 화면은 껍데기라도 만들지 않는다.
주문서까지는 만들되 **결제 단계 직전에서 멈춘다.**

## 구현 메모

- 화면 전환은 **한 파일 안 뷰 스위칭**으로 한다 (자체완결 규격 유지)
- 탭은 DOM 골격을 유지하고 **데이터만 갈아끼운다** — 원본이 그렇게 한다
- 카테고리 10종은 **한 목록 화면 + 데이터**로 접는다
- 이미지는 원본 비율 슬롯(정사각 150·255·327 · 가로 1.31 · 세로 0.80)에
  **발명한 브랜드에 맞는 실사**를 넣는다. 원본 이미지는 가져오지 않는다

## 구현 결과 — `templates/ref-07-lge-ondam.html`

설계서 확정 범위 6화면을 **한 파일 안 뷰 스위칭**으로 구현했다.

| # | 화면 | 구현 | 실측 확인 |
|---|---|---|---|
| 1 | 홈 | `#v-home` | 섹션 좌표 **17/17** 유지 |
| 2 | GNB 드롭다운 | 호버 · 대분류 5 × 소분류 4 | 열림/닫힘 확인 |
| 3 | 카테고리 목록 | `#v-list` · 필터 + 정렬 | 분류별 3~7개 · 전체 26개 |
| 4 | 제품 상세 | `#v-detail` · 갤러리 5장 + 스펙 5행 + 수량 | 카드 클릭 → 전환 확인 |
| 5 | 장바구니 | 드로어 + 스크림 | 담기 → 뱃지 2 · 합계 1,404,480원 · 삭제 → 빈 상태 |
| 6 | 검색 결과 | `#v-search` | "냉장" 1건 · 없는 말 → 빈 상태 |

**동선 전체를 실제로 눌러 확인했다.**
홈 → GNB → 목록 → 정렬 전환 → 카드 → 상세 → 수량 → 담기 → 장바구니 → 삭제 → 검색.

### 설계서가 실제로 구현을 바꾼 지점

- **탭은 데이터만 갈아끼운다** — 답사에서 원본 탭이 노드·높이를 안 바꾸는 걸 확인했다.
  구현도 DOM 골격을 유지하고 카드만 다시 그린다
- **카테고리 10종을 한 화면으로 접었다** — 답사에서 라우트를 세어 보고 정한 것이다.
  화면을 10개 만들었으면 뼈대가 열 배로 늘었다
- **결제는 만들지 않았다** — 주문서 버튼을 누르면 "결제 단계는 이 견본에 없습니다"로 멈춘다

### 구현 중 잡은 결함

**390px에서 헤더가 넘쳤다**(`scrollWidth 424`). 검색창과 장바구니 버튼을 나란히 둔 탓이다.
모바일에서 검색창을 접어 375로 되돌렸다. 홈만 재던 때는 없던 결함이고,
**새 화면을 붙이면 기존 폭 검증을 다시 해야 한다**는 뜻이다.

### 남은 것

이미지가 아직 회색 슬롯이다. 원본 비율(정사각 150·255·327 · 가로 1.31 · 세로 0.80)은
맞춰 뒀으므로, 발명한 브랜드에 맞는 실사를 같은 자리에 넣으면 된다.
컨택트시트로 눈으로 확인하는 단계가 필요해 디스크 여유가 있을 때 진행한다.

## 사진 — 회색 슬롯을 실사로 교체

Unsplash 무료 이미지 14장을 제품군마다 배정했다. 원본 이미지는 쓰지 않고
**원본이 쓰던 비율(정사각 · 1.31 · 0.8)만 그대로** 두고 그 자리에 채웠다.
크롭·해상도·품질은 URL 파라미터로 슬롯마다 따로 잡는다.

### 컨택트시트에서 걸러낸 것

- **BLUEAIR 로고가 찍힌 공기청정기 컷** — 상표 노출이라 제외
- **"식기세척기" 캡션인데 실제로는 조리대인 컷** — 그 용도로 쓰지 않고 주방 일반으로 돌렸다

### 넣고 나서 잡은 결함 둘

**① 이름 첫 단어로만 매핑해 엉뚱한 사진이 붙었다.**
`"헹굼 식기 12인"`(식기세척기)이 `"헹굼"`(세탁기) 사진을 물어왔다.
전체 이름을 먼저 찾고 없을 때만 첫 단어로 떨어지도록 고쳤다.

**② ★ 컨택트시트에서 본 것과 화면에 나온 것이 달랐다.**
시트는 기본 크롭으로 봤는데 슬롯은 `crop=entropy` 였다.
같은 사진인데 **다른 영역이 잘려**, 건조기 카드에 창가 화분이 나왔다.
`crop=entropy` 를 빼서 시트와 같은 크롭으로 맞췄다.

> **비율이 다르면 같은 사진도 다른 사진이 된다.**
> 컨택트시트는 실제 슬롯과 **같은 크롭 방식**으로 봐야 한다.
> 이 저장소의 「사진은 눈으로 확인할 것」 규칙에 한 줄이 더 붙는다 —
> 확인할 때와 쓸 때의 크롭이 같아야 한다.

실측: 이미지 40장 전부 로드, 상세 갤러리 메인 900px, 썸네일 5장(크롭 위치를 달리해 각도 차이를 냄).
