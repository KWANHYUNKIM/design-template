# 페이지 복제 — 뼈대까지 옮긴다

`design-ref` 는 **토큰**을 옮긴다(타입·간격·색·라운드·그림자·모션).
그것만으로도 숫자는 맞지만 **안 닮아 보인다.** 뼈대가 다르기 때문이다.

> REF 06은 LG 시스템을 6축 전부 맞췄는데도 "왜 안 똑같냐"는 말이 나왔다.
> 자간 3단계·16px 간격·2겹 그림자까지 같았지만,
> 원본은 히어로 캐러셀 → 프로모션 타일 → 카테고리 그리드 순이고
> 산출물은 계산기 → 카드 → 후기 순이었다. **구성이 달랐다.**

이 스킬은 그 층을 마저 옮긴다.

## 두 가지 출력 모드 — 먼저 정한다

| 모드 | 출력 위치 | 얼마나 닮는가 | 공개 |
|---|---|---|---|
| **연구용 클론** | `_clone/<회사>/` | 뼈대·비율·좌표까지 최대한 | ❌ 커밋·배포 안 함 |
| **공개 산출물** | `templates/ref-NN-*.html` | 뼈대는 같고 **브랜드·콘텐츠는 발명** | ✅ 갤러리에 올림 |

**연구용 클론은 구조를 익히려고 만드는 것이다.** 클론 코딩은 디자인 교육의 표준 방식이고,
남의 페이지를 뜯어 보며 배우는 것 자체는 정상적인 작업이다.
다만 그 결과물을 **그대로 공개하면** 성격이 달라진다.

`_clone/` 은 `.gitignore` 에 넣어 커밋되지 않게 한다.

## 선 — 공개 산출물에만 적용된다

공개하는 순간 아래는 못 가져온다. 취향이 아니라 사칭이 되는 지점이다.

- ❌ 로고·워드마크·브랜드 심볼
- ❌ 실제 제품명 (그 회사가 파는 물건의 이름)
- ❌ 그 회사의 사진·일러스트·아이콘 원본
- ❌ 실제 카피 문장
- ❌ 그 회사인 것처럼 보이게 하는 모든 것 — 회사명·도메인·실존 인물

**뼈대·비율·컴포넌트 구성·좌표는 가져온다.** 이건 어느 회사의 소유물도 아니다.
`scripts/verify.mjs` 의 `ref-*` 검사 3종이 자동으로 막는다.

## 두 역할로 나눈다 — 설계가 먼저다

측정만 하면 **정지된 한 장**밖에 못 만든다.
클릭하면 무엇이 열리는지, 어디로 가는지는 걸어 다녀야 안다.

| 역할 | 하는 일 | 산출물 |
|---|---|---|
| **① 설계 (답사)** | 사이트를 실제로 클릭해 다니며 화면·플로우·상태를 목록화하고 **범위를 정한다** | `refs/<회사>/survey.md` |
| **② 구현** | 설계서의 화면 목록 순서대로 뼈대를 세우고 채운다 | `templates/ref-NN-*.html` |

**설계서 없이 구현을 시작하지 않는다.** 범위를 모른 채 지으면
카드를 다 만든 뒤에 "누르면 상세가 떠야 하네"를 알게 되고, 그때 뼈대를 다시 짠다.

설계서가 답해야 할 질문은 하나다 — **어디까지 만들 것인가.**
`복제` 열에 ❌ 를 적는 것이 그 문서의 핵심이다. 전부 만들 수는 없다.

절차는 `references/survey.md` 에 있다.

## 실행 그래프 — 승인 없이 자동으로 돈다

이 스킬은 **노드 그래프로 실행한다.** 창작하지 않는다. **원본 재현이 유일한 목표다.**

```
[공유 상태] → N1 분석/스펙추출 → N2 재현 → N3 비교검증 ─(차이 있음, ≤3회)─┐
                                              │                          │
                                              └─(차이 없음)→ N4 출력      │
                                              ▲                          │
                                              └──────────────────────────┘
```

**진행 규칙**

- **승인 지점이 없다.** 중간에 멈춰 묻지 않고 N4까지 자동으로 간다
- 노드가 끝날 때마다 **현재 노드만 한 줄로 표시**한다 (`■ N2 재현 완료 → N3`)
- N3는 **조건부 엣지**다. 차이가 남아 있으면 그 부분만 고쳐 N3를 다시 돈다. **최대 3회.**
  3회를 넘겨도 남으면 고치지 말고 N4의 「불가피한 차이」에 사유와 함께 적는다
- **원본에 없는 요소를 추가하거나 "개선"하지 않는다.** 더 나아 보여도 원본대로 둔다

**공유 상태 — 시작 전에 채운다**

```
레퍼런스   : URL 또는 이미지
결과물 형식 : HTML/CSS · Figma 프레임 · 코드 컴포넌트
복제 범위   : 전체 페이지 / 특정 섹션 / 특정 화면
출력 모드   : 연구용(_clone/) · 공개용(templates/ref-NN-*)
```

빈칸이 있으면 **묻지 말고 합리적 기본값으로 채운 뒤 N4에서 무엇을 가정했는지 밝힌다.**
자동 실행이 이 그래프의 전제다.

### N1 · 분석 / 스펙 추출

`references/survey.md` + `references/deep-extract.md` 를 돌려 **스펙 문서**를 만든다.
**이 스펙이 이후 모든 노드의 유일한 기준이다.**

1. **레이아웃** — 섹션 시퀀스·y좌표·높이·그리드 열수·gap·최대폭
2. **컬러** — 배경/텍스트/포인트 HEX와 **사용 빈도**, 포인트색이 쓰인 자리
3. **타이포** — 크기·굵기·행간·자간. 40px 이상은 `chars`·`lines`·`whiteSpace` 까지
4. **간격** — padding·margin 값의 빈도 분포와 기준 단위
5. **컴포넌트** — 버튼·카드·아이콘의 형태와 라운드 값, **개수**
6. **상태** — 클릭하면 무엇이 열리는가 (페이지이동/모달/인플레이스/펼침)

산출: `refs/<대상>.md` (시스템) + `refs/<대상>-survey.md` (화면·범위)

### N2 · 재현

**N1의 스펙만 근거로 만든다.** 기억이나 관행으로 채우지 않는다 —
스펙에 없으면 원본을 다시 재고 스펙에 추가한 뒤 쓴다.

`references/rebuild.md` 의 순서를 따른다: 골격(회색 상자) → 그리드 → 슬롯 → 타입 → 콘텐츠.

### N3 · 비교 검증 · 조건부 엣지 (최대 3회)

같은 추출 스크립트를 산출물에 돌려 **표로 대조한다.**

| 축 | 합격선 |
|---|---|
| ① 레이아웃 | 섹션 높이 ±15% · 그리드 열수 전 구간 일치 · 컴포넌트 개수 ±1 |
| ② 컬러 | 최다 텍스트색 일치 · 포인트색이 쓰인 **자리의 종류** 일치 |
| ③ 타이포 | 상위 6단계 중 4개 이상 ±1px · 자간 단계 수 일치 |
| ④ 간격 | 기준 단위 일치 · 상위 8개 중 6개 이상 일치 |

**차이가 있으면 그 부분만 고쳐 N3를 다시 돈다.** 회차와 무엇을 고쳤는지 기록한다.
안 맞는 축이 나오면 먼저 **"내 습관인가 구조 차이인가"** 를 묻는다 —
습관이면 고치고, 구조 차이면 N4에 적고 둔다. 태그별로 쪼개 보면 갈린다.

### N4 · 출력

최종 결과물 + **원본과 불가피하게 다른 부분과 그 이유** 목록.

불가피한 차이의 예 — 폰트 미보유 · 원본 이미지 미사용(선) · 브랜드 자산 미사용(선) ·
표본 크기 차이로 컴포넌트 종수가 적음 · 인증/결제 화면 미구현(선).

**"안 맞았지만 못 고쳤다"와 "일부러 안 했다"를 구분해서 적는다.**

## 순서 (노드별 세부)

### 1. 모드 결정

연구용인지 공개용인지 **먼저** 정한다. 나중에 바꾸면 콘텐츠를 전부 다시 써야 한다.

### 2. 답사 — `references/survey.md` · **여기서 범위가 정해진다**

클릭 가능한 것을 전부 세고, 각각이 **페이지 이동 / 모달 / 인플레이스 전환 / 펼침**
중 무엇인지 누르기 전후를 비교해 가른다. 빈 상태·에러 상태도 직접 만들어 본다.

설계서를 쓰고 **범위 판정**(만든다 / 안 만든다)을 확정한 뒤에 다음으로 간다.

### 3. 깊은 추출 — `references/deep-extract.md`

`design-ref` 의 추출이 **분포**를 잰다면 이쪽은 **구조**를 뜬다.

```
① 섹션 골격    각 섹션의 역할·높이·배경·자식 컴포넌트 수
② 그리드 지도  grid/flex 컨테이너마다 열 구성·gap·자식 수
③ 컴포넌트 인벤토리  반복되는 블록의 종류와 개수 (카드 24개, 배너 4개…)
④ 이미지 슬롯  각 이미지의 표시 크기·비율·object-fit·섹션 내 위치
⑤ 타입 역할표  크기별로 "어디에 쓰였는지" (h1 자리인가 캡션 자리인가)
⑥ 좌표         주요 블록의 x·y·w·h — 겹침과 정렬을 재현하는 데 쓴다
```

**끝까지 스크롤한 뒤 잰다.** 캐러셀·아코디언은 각 상태를 따로 잰다.

### 4. 골격 먼저 세운다 — 콘텐츠는 나중

**빈 상자로 페이지를 먼저 완성한다.** 섹션 높이·그리드 열수·이미지 슬롯을 회색 박스로 두고,
원본과 좌표를 대조해 뼈대가 맞을 때까지 조정한다.

콘텐츠를 먼저 넣으면 텍스트 길이에 밀려 뼈대가 어긋나고, 그때는 원인을 못 찾는다.

### 5. 콘텐츠를 채운다

- **연구용:** 원본과 같은 자리에 같은 성격의 더미를 넣는다(길이만 맞춘다)
- **공개용:** 발명한 브랜드·제품·수치로 채우되 **글자 수 대역을 맞춘다.**
  원본 제품명이 6~10자면 발명한 이름도 그 대역으로 — 안 그러면 카드가 다르게 접힌다

### 6. 좌표 대조 — 이 스킬의 합격선

같은 추출 스크립트를 산출물에 돌려 **블록별 좌표를 대조한다.**

| 축 | 합격선 |
|---|---|
| 섹션 높이 | 각 섹션 ±15% |
| 그리드 열수 | 전 구간 일치 |
| 컴포넌트 개수 | 카드·배너·버튼 수 ±1 |
| 이미지 슬롯 비율 | ±0.05 |
| 주요 블록 y좌표 | 누적 오차 ±10% |
| 타입 역할 | 크기별 쓰임이 같은 자리 |

**높이가 15%를 넘게 벌어지면 콘텐츠 분량이 다른 것이다.** 글자 수를 조정한다.

### 7. 검증 · 기록

`design-ref` 와 같다 — `verify.mjs` 오류 0, iframe 실측 3폭, 선 검사 3종.
공개 산출물이면 `refs/<회사>.md` 에 좌표 대조표를 append 한다.

## design-ref 와의 관계

| | design-ref | design-clone |
|---|---|---|
| 재는 것 | 값의 **분포** | 구조의 **좌표** |
| 결과 | 같은 시스템, 다른 물건 | **같은 뼈대**, 다른 브랜드 |
| 쓸 때 | 시스템을 배우고 싶을 때 | 그 페이지처럼 보이게 하고 싶을 때 |

**둘을 같이 쓴다.** design-ref 로 토큰을 잡고, design-clone 으로 뼈대를 세운다.
토큰만 맞추면 안 닮고, 뼈대만 맞추면 싸구려 모조가 된다.
