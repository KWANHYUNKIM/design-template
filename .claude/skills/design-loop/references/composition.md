# 구성 대장 — 페이지가 닫히는 방식과 골격 관용구

`animate` 의 기법 대장이 **모션**의 중복을 막는다면, 이 문서는 **구성**의 중복을 막는다.

## 왜 이 문서가 생겼는가

28장을 실제로 대조한 결과다. 브랜드·카피·수치는 매번 새로 발명되는데 **골격은 수렴했다.**

| 항목 | 28장 중 |
|---|---|
| `IntersectionObserver` + `.rise` 리빌 | **28** |
| `.wrap` 컨테이너 | 25 (30이 처음으로 안 씀) |
| 마지막 섹션이 전환/닫는 블록 | 24 |
| 증언·리뷰 섹션 보유 | 20 |
| 「라벨 + `h2` + lead」 섹션 헤더 관용구 (RUN17 이후) | 파일당 4~10회 |
| `<table>` 을 실제로 쓴 것 | 3 (25·26·30) — 대부분 div 격자로 짠다 |

이 사실은 이미 세 군데에 적혀 있었다 — `EVOLUTION.md` 약점 패턴,
`EVOLUTION.md` RUN21 교훈("꼬리를 재사용하면 순서 파괴는 무효"), `SKILL.md` "점수가 막혔을 때".
**세 번 다 문장이었고, 세 번 다 무시됐다.** RUN21·23·25가 그 기록이다.
그래서 문장이 아니라 **만들기 전에 통과해야 하는 관문**으로 옮겼다.

## 1. 닫는 방식 대장

페이지의 **마지막 섹션**이 무엇이었는가. 이게 "구성이 비슷하다"의 정체다.

| 닫는 방식 | 쓴 RUN | 판단 |
|---|---|---|
| **헤드라인 + 버튼 CTA 밴드** (다크 풀블리드 다수) | **14** — 04·05·08·09·11·12·13·14·15·16·18·21·22·23 | **소진.** 새 RUN에서 금지 |
| 뉴스레터 · 레터 구독 | 4 — 01·02·03·06 | **소진** |
| 문의 · 예약 · 주문 폼 | 3 — 07·19·20 | **소진** |
| 리뷰/평점으로 닫음 | 1 — 10 | 재사용 시 변주 필수 |
| 문서형 마무리 (각주 · 개정 이력) | 1 — 17 | 여지 있음 |
| 이용 안내 · 주의사항 (「타기 전에」) | 1 — 25 | 여지 있음 |
| 판권 · 콜로폰 | 1 — 24 | 여지 있음 |
| 탈락 체크리스트 (걸리면 못 산다) | 1 — 26 | 여지 있음 |
| 「우리가 만들지 않는 것」 선언 | 1 — 29 | 여지 있음 |
| **자사 실패·폐기 기록** (올해 버린 것과 그 사유) | **2** — 30 · 32 | 두 RUN 연속. 다음 사용 시 변주 필수 |
| **용어 사전** (이 문서에 쓴 말) | 1 — 31 | 여지 있음 |
| **만든 사람들의 이견** (같은 것을 두고 갈린 말) | 1 — 33 | 여지 있음 |
| **대기자 명단의 현재 길이** (지금 줄 서 있는 사람들) | 1 — 34 | 여지 있음 |

**28장 중 21장이 "권유형 닫기"** (CTA 밴드 + 뉴스레터 + 폼)다.
깬 것은 최근 7장 중 5장(24·25·26·29·30)뿐이고, 전부 **버튼 없이 닫았다.**

> ⚠️ **거절형이 26·29 연속으로 나왔다.** 「탈락 체크리스트」와 「우리가 만들지 않는 것」은
> 둘 다 *구매자를 거르는* 닫기다. RUN30이 세 번째로 그쪽을 골랐다면 그것도 수렴이었을 것이다.
> RUN30은 방향을 뒤집어 **자사의 실패를 공개하는** 쪽으로 닫았다.
> 닫는 방식을 셀 때는 형식(버튼 유무)만 보지 말고 **누구를 향하는가**까지 볼 것.

RUN26은 KELVIN 꼬리 3모듈을 통째로 폐기하고 체크리스트로 닫아 임팩트 5·모션 5를 받았다.

> 닫는 방식을 바꾼다는 건 CTA 문구를 바꾸는 게 아니라
> **마지막 화면에서 독자에게 시키는 행동의 종류**를 바꾸는 것이다.
> "사세요"가 아니라 — 재보게 하거나, 포기시키거나, 기록으로 남기거나, 다음을 예고하거나.

### 아직 아무도 안 쓴 닫는 방식 (참고)

색인·찾아보기 / ~~오답·실패 사례~~(30·32) / 반품·해지 절차 / ~~용어 사전~~(31) / ~~만든 사람들의 이견~~(33) /
측정 원본 데이터 덤프 / ~~이 페이지의 유효기간~~(31) / ~~경쟁사를 추천~~(35) / ~~대기자 명단의 현재 길이~~(34)

남은 것은 **셋뿐이다** — 색인·찾아보기 / 반품·해지 절차 / 측정 원본 데이터 덤프.
소진되면 새 방식을 발명해 이 줄에 적는다. 「행동의 종류」가 다르면 새 것이다.

## 2. 증언의 자리 대장

증언 섹션 자체가 문제가 아니다. **놓이는 위치가 고정된 것**이 문제다.

증언이 **마지막 4섹션 안**에 들어간 RUN: 16 · 17 · 18 · 19 · 21 · 23 · 24 · 26 · 29 — **9개.**
앞자리로 올린 RUN: **30**(2번째 — 추천사가 책 앞에 오는 편집 관례). 이게 꼬리 구조 자체를 갈랐다.
그중 「증언 → (가격 또는 FAQ) → 닫기」 순서를 그대로 쓴 RUN:
**16 · 18 · 19 · 20 · 21 · 22 · 23 · 26 — 최근 12장 중 8장.**

- 증언을 쓰려면 **앞쪽 절반**에 두거나, 다른 섹션 안으로 녹인다
- 「증언 → 가격 → CTA」 3연은 **그대로 재사용 금지**
- 제3자 신호는 증언 블록 말고도 만들어진다 — RUN17의 「남이 우리에 대해 쓴 것」,
  RUN25의 「이 안내의 근거」(인가·정시율·민원 + 출처)가 그 예다

## 3. 골격 관용구 대장

섹션 순서를 바꿔도 **안쪽이 같은 문법이면** 여전히 같은 페이지로 읽힌다.

| 관용구 | 쓴 RUN 수 | 지시 |
|---|---|---|
| `IntersectionObserver` + `.rise` 로 섹션 진입 리빌 | **28 / 28** | 기본기. 이걸 **주된** 모션으로 삼지 말 것 (`animate` 기법 대장) |
| `.wrap` 최대폭 컨테이너 + 좌우 패딩 | 25 | 써도 되지만, **전 섹션이 같은 폭이면** 여백 점수가 3에 묶인다 |
| 섹션 헤더 = 작은 라벨(`eyb`/`lbl`) + `h2` + lead 문단 | RUN17 이후 파일당 4~10회 | **한 페이지에서 3회 이상 쓰지 말 것.** 나머지는 다른 진입 방식으로 |
| 전 섹션 동일 세로 패딩 (`s8`/`s9`) | RUN26 감점 사유 | 섹션마다 호흡을 바꾼다 |
| 좌우 여백이 전 섹션 동일 | 29 / 30 중 29 | RUN30은 `.sheet`(좌40·우80)와 `.sheet-n`(좌80·우40)을 **교대**시켜 여백 5점을 받았다 |

RUN26은 여백 3 · 완성도 3을 받았고 사유가 **"다섯 섹션이 전부 같은 패딩"** 이었다.
관용구는 개별로는 무해하고, **겹쳐 쌓일 때** 점수를 깎는다.

## 3.5 AD별 이력 대장 — 슬롯 안에서 또 수렴한다

디렉터 제도는 수렴을 깨려고 만든 것인데, **같은 AD 슬롯이 돌아오면 그 안에서 다시 수렴한다.**
RUN25와 RUN31은 둘 다 AD-1인데 크림 지면 + 마스트헤드 + 헤어라인 괘선 + 표 3개 +
한국어 공공 문서로 겹쳤고, `--rule2` 가 `#a9a49a` / `#a9a596` 으로 사실상 같은 값이었다.
**AD를 배정받으면 이 표에서 그 AD가 지난번에 무엇을 했는지 먼저 본다.**

| AD | RUN | 범주 | 바탕 | 포인트색 | 시그니처 |
|---|---|---|---|---|---|

## 4. 구성 선언 양식 (관문)

HTML을 **한 줄도 쓰기 전에** 아래를 말로 채운다. 채우지 못하면 아직 만들 준비가 안 된 것이다.

```
섹션 역할 시퀀스 :  (예) tool → hero → why → tide → trust → alerts → close
닫는 방식        :  대장 어느 행인가 / 대장에 없는 새 방식인가
증언의 위치      :  n번째 섹션 (마지막 4개 안이면 사유를 적는다)
리빌 외 주 모션  :  (animate 기법 대장에서 고른 것)
섹션 헤더 변주   :  라벨+h2+lead 를 쓰는 섹션 수 / 나머지는 어떤 진입인가
직전 3개 RUN 시퀀스와의 겹침 : 연속 일치한 최장 구간 __개
```

시퀀스 대조는 눈대중으로 하지 말고 실제로 뽑아 본다.

```bash
for f in templates/run-*.html; do
  echo "=== $(basename $f)"
  grep -oE '<(section|footer)[^>]*class="[^"]*"' "$f" | sed -E 's/.*class="([^"]*)".*/\1/'
done
```

### 통과 조건 — 하나라도 걸리면 되돌아가 다시 짠다

1. **닫는 방식이 대장의 "소진" 3행 중 하나가 아니다**
   (CTA 밴드 · 뉴스레터 · 문의/예약/주문 폼)
2. **꼬리 3섹션의 역할 조합이 직전 3개 RUN 중 어느 것과도 일치하지 않는다**
3. **직전 3개 RUN과 연속 일치한 시퀀스 구간이 2개 이하다**
4. **「증언 → 가격/FAQ → 닫기」 3연을 쓰지 않는다**
5. **`IntersectionObserver` 리빌이 이 페이지의 유일한 모션이 아니다**
6. **라벨+`h2`+lead 섹션 헤더가 3회 이하다**
7. **같은 AD의 직전 RUN과 골격을 공유하지 않는다** — §3.5를 눈으로 보는 것만으로는 안 지켜졌다(RUN33).
   만들기 전에 **재서** 통과시킨다:

   ```bash
   node scripts/skel.mjs run-NN-slug --ad AD-1     # 같은 AD 슬롯 전부와 대조
   node scripts/skel.mjs run-NN-slug run-30-smin   # 특정 RUN 하고만
   ```

   - ⓐ 공유 클래스 **5개 이하**
   - ⓑ 동일 골격 규칙 **10% 이하**
   - ⓒ 같은 이름의 섹션 컴포넌트(`.voices`·`.q`·`.bars` 등) **재사용 금지**

   > ⚠️ **줄 단위로 세면 안 된다.** RUN34에서 전체 CSS 줄로 재니 22%가 나왔는데,
   > 겹치는 줄이 **거의 전부 규격이 강제하는 것**이었다 — `:root` 토큰 스케일 ·
   > 스크롤 복원 가드(함정 5) · `.js` 리빌 게이트(함정 16) · `?capture=1` ·
   > `.fold` 표 접기(함정 12·13) · CSS 리셋. **규격을 지킬수록 관문에 걸리는 모순이었다.**
   > `skel.mjs` 는 요소 리셋과 규격 강제 블록을 빼고 **그 RUN이 직접 지은 클래스 규칙만** 센다.
   >
   > 그 기준으로 다시 재면 — RUN31↔34는 **1.0%**(골격을 새로 짠 것이 맞았다),
   > RUN30↔33은 **11개 클래스 · 12.2%**(`.q`·`.qs`·`.voices` 인용 컴포넌트가 통째 이식돼 있었다).
   > 측정을 고치니 무죄와 유죄가 갈렸다.

3번이 리믹스 RUN(짝수)에서 걸릴 때는 **골격을 계승하되 닫는 방식과 꼬리는 새로 짠다.**
계승해야 할 것은 시그니처(팔레트·타입·핵심 인터랙션)이지 모듈 순서가 아니다.

> **RUN30 실적:** 관문 6조건을 통과시킨 결과 크리틱이 **오리지널리티 5 · 여백 5 · 구성 대조 6/6 통과**를
> 줬다. 이 저장소에서 오리지널리티 5는 17·18 이후 세 번째다. 관문은 작동한다.
> 다만 관문은 **구성**만 지킨다 — RUN30이 35에서 멈춘 이유는 완성도(3)였다.

## 5. 기록

RUN을 끝내면 이 문서의 **1·2·3 표에 그 RUN을 추가한다.**
새 닫는 방식을 발명했으면 §1에 행을 만들고, §1 말미의 "아직 안 쓴" 목록에서 지운다.
갱신하지 않으면 다음 RUN이 같은 것을 또 쓴다 — 이 문서가 무력해지는 유일한 경로다.
