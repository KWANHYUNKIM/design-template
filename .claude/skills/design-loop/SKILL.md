# 디자인 진화 루프

랜딩 템플릿을 **한 번에 찍어내지 않고, 하나씩 만들어 채점하고 다음이 그 점수를 넘으려 하는** 루프다.
다양성만으로는 좋아지지 않는다. 매 RUN이 평가·학습·챔피언 초과를 거친다.

## 시작 전에 반드시 읽을 것

1. `EVOLUTION.md` — 현재 챔피언 · 검증된 학습 · 약점 패턴 · 점수 이력
2. `art-directors.md` — 아트디렉터 3종의 do/don't
3. `design-automation-workflow.md` — §A-5 구조 프리셋 · §C 체크리스트 · §D 함정
4. `references/composition.md` — **구성 대장.** 닫는 방식 · 증언 자리 · 골격 관용구

**학습을 반영하고 약점 패턴을 회피하는 것이 이 루프의 전부다.** 읽지 않고 시작하면 같은 실수를 반복한다.

28장을 대조해 보면 브랜드·카피·수치는 매번 새로 발명되는데 **골격은 수렴했다** —
마지막 섹션이 전환 블록인 것이 24장, 증언 섹션이 20장, 리빌이 IO+`.rise` 그대로인 것이 28장 전부.
이 사실은 이 파일에도 `EVOLUTION.md` 에도 적혀 있었지만 **문장이라서 무시됐다.**
그래서 5단계를 **통과하지 못하면 생성으로 넘어갈 수 없는 관문**으로 만들었다.

## 함께 쓰는 스킬

이 루프는 혼자 굴러가지 않는다. 아래를 **해당 단계에서 실제로 발동한다.**

| 스킬 | 언제 | 무엇을 |
|---|---|---|
| **taste** | 3단계 전 · 8단계 끝 | 미감 방향 확정 · 진부함 목록 대조 · 자가 대조 6문항 |
| **animate** | 5 · 6단계 | 기법 대장 대조 · 조작형 인터랙션 1종 설계 · 폴백 4종 |
| `frontend-design` | 방향이 안 잡힐 때 | 일반 지침. 구체적 판단은 `taste`로 내린다 |
| `claude-in-chrome` | 8단계 | 실제 크롬 탭에서 3폭 검증 |
| `playwright` | 8단계 반복 | 헤드리스 캡처를 스크립트로 반복할 때 |

`references/composition.md`(구성 대장)는 스킬이 아니라 이 스킬의 참조 문서지만,
**5단계에서 기법 대장과 같은 방식으로 대조한다.**

## 실행 그래프 — 승인 지점 2개

아래 11단계는 **노드 그래프로 실행한다.** 단계 번호는 그대로 두고, 노드가 그 위에 얹힌다.

```
[브리프] → N1 팬아웃(3안 병렬) → ◆승인1 → N2 종합/발전 → N3 검증 ─(미달, ≤2회)─┐
                                                            │                  │
                                                            └─(통과)→ ◆승인2 → N4 출력
                                                            ▲                  │
                                                            └──────────────────┘
```

| 노드 | 하는 일 | 아래 단계 |
|---|---|---|
| **N1 팬아웃** | 방향이 뚜렷이 다른 시안 **3안**을 병렬로 낸다 | 1~4 |
| **◆승인1** | **멈춘다.** 사용자 선택을 기다린다 (조합 지시 가능) | — |
| **N2 종합** | 선택된 방향으로 완성안 1개 | 5~7 |
| **N3 검증** | 체크리스트 자체 평가 · 미달만 고쳐 재실행 **최대 2회** | 8 |
| **◆승인2** | **멈춘다.** 최종 확정 전 승인 대기 | — |
| **N4 출력** | 최종안 + 주요 결정 3가지 + 기록·커밋 | 9~11 |

노드가 끝날 때마다 **현재 노드를 한 줄로 표시**한다 (`■ N1 팬아웃 완료 → 승인1 대기`).

### 브리프 — 비면 실행 전에 묻는다

```
만들 것   : 랜딩 1장 / 로고 / 카드뉴스 …
목적      :        타깃      :        톤앤매너 :
필수 요소 : 브랜드 컬러·로고·수치 등
금지 사항 : 그라데이션 금지 등
```

**모든 노드는 이 브리프 기준이다. 임의로 벗어나지 않는다.**
이 저장소에서 돌릴 때는 `EVOLUTION.md` 의 챔피언·학습·약점 패턴이 브리프에 자동으로 얹힌다.

### N1 · 팬아웃 — 방향이 겹치면 팬아웃이 아니다

시안 3개는 **아카이타입이 서로 달라야** 한다. 색만 바꾼 셋은 한 안이다.

- **A안 — 여백 중심 미니멀**
- **B안 — 대담한 타이포그래피 중심**
- **C안 — 일러스트/그래픽 중심**

각 안마다 **콘셉트 2줄 + 결과물**. 배정된 아트디렉터의 don't는 세 안 모두에 적용된다.

> 이 저장소는 아트디렉터 3인이 이미 팬아웃 장치다.
> 셋을 한 RUN에 동시에 쓰면 A·B·C가 자연히 갈린다.

### N3 · 검증 — 조건부 엣지 (최대 2회)

| 항목 | 통과 기준 |
|---|---|
| ① 필수 요소 반영 | 브리프의 필수 요소가 전부 들어갔는가 |
| ② 금지 사항 위반 없음 | 금지 목록 + 배정 AD의 don't |
| ③ 타깃에 맞는 톤 | `taste` 진부함 목록에 걸리지 않는가 |
| ④ 가독성·시인성 | 대비 실측 AA · 390/1024/1440 3폭 |

**미달 항목만 고쳐 재실행한다.** 2회를 넘겨도 미달이면 고치지 말고 N4에 사유를 적는다.

### N4 · 출력

최종안 + **주요 결정 3가지** 요약 + `EVOLUTION.md`·`log.html`·`index.html` 기록 + 커밋.

## 순서 (노드별 세부)

### 1. 아트디렉터 배정 (가장 먼저)
`RUN 번호 % 3` 으로 배정. 연속 두 RUN이 같은 디렉터를 받지 않는다.
배정된 디렉터의 **do와 don't를 둘 다** 지킨다. don't 위반은 완성도 −1.
화면에 디렉터 이름을 노출하지 않는다.

### 2. 방향 결정
- **홀수 RUN = 새 방향** — 아카이타입(페이지의 종류 자체)을 이전 RUN들과 다르게 발명
- **짝수 RUN = 챔피언 리믹스** — 계승하되 강화. 골격만 재사용하면 오리지널리티가 정체된다
- 리믹스 대상은 "약점이 뚜렷한 것"이 아니라 **총점이 높은 것**을 고른다 (RUN23 교훈)

### 3. 컨셉·콘텐츠 발명 — **`taste` 스킬을 먼저 발동한다**
브랜드·서사·섹션 주제·카피·수치·리뷰를 **직접 창작**한다. 템플릿 채우기가 아니다.
발명한 수치는 현실적으로, 단위와 라벨의 의미가 일치해야 한다.

`taste` 의 **만들기 전 4문장**(임무 · 주제의 재료 · 감수하는 위험 · 닫히는 방식)을
말로 먼저 확정한다. 채우지 못하면 아직 만들 준비가 안 된 것이다.
방향 자체가 안 잡히면 `frontend-design` 을 먼저 읽고 온다.

### 4. 이미지 선정 — 컨택트시트로 눈으로 볼 것
`curl 200` 은 "뜨는가"만 보장하고 **"그 이미지가 맞는가"는 보장하지 않는다.**
후보를 한 페이지에 모아 띄워 실제 피사체를 확인한다. 이 단계를 건너뛰면
"CNC 캡션 아래 석유화학 플랜트"(RUN21), "갯벌 앱에 콜로세움"(RUN23 후보) 같은 사고가 난다.
기존 RUN이 쓴 ID와 겹치지 않게 `grep -oh "photo-[a-zA-Z0-9_-]*" templates/*.html` 로 대조한다.

### 5. 구성 선언 — **관문. 통과 못 하면 생성으로 못 넘어간다**

HTML을 **한 줄도 쓰기 전에** `references/composition.md` 를 열고 대조한다.
"이번엔 다르게 하겠다"는 다짐이 아니라, **아래를 말로 채워 답한 뒤**에 진행한다.

```
섹션 역할 시퀀스 :  hero → … → close
닫는 방식        :  대장 어느 행인가 / 새 방식인가
증언의 위치      :  n번째 (마지막 4개 안이면 사유)
리빌 외 주 모션  :  animate 기법 대장에서 고른 것
섹션 헤더 변주   :  라벨+h2+lead 쓰는 섹션 수 / 나머지 진입 방식
직전 3개 RUN과의 최장 연속 일치 : __개
```

직전 3개 RUN의 시퀀스는 눈대중 말고 실제로 뽑아 본다.

```bash
for f in templates/run-*.html; do echo "=== $(basename $f)"; \
  grep -oE '<(section|footer)[^>]*class="[^"]*"' "$f" | sed -E 's/.*class="([^"]*)".*/\1/'; done
```

**통과 조건 6개 — 하나라도 걸리면 되돌아가 다시 짠다** (근거·전체 목록은 구성 대장):

0. **배정된 AD가 지난번에 무엇을 했는지 구성 대장 §3.5에서 먼저 본다** — 바탕색·포인트색·범주·시그니처를
   그대로 반복하지 않는다. RUN25와 RUN31이 둘 다 AD-1인데 크림 지면 + 괘선 + 표 3개 + 공공 문서로 겹쳤다
1. 닫는 방식이 **CTA 밴드 · 뉴스레터 · 문의/예약/주문 폼**이 아니다 (이 셋은 28장 중 21장이 써서 소진)
2. 꼬리 3섹션의 역할 조합이 직전 3개 RUN 중 어느 것과도 일치하지 않는다
3. 직전 3개 RUN과 연속 일치한 시퀀스 구간이 2개 이하다
4. 「증언 → 가격/FAQ → 닫기」 3연을 쓰지 않는다 (최근 12장 중 8장이 이 순서)
5. IntersectionObserver 리빌이 이 페이지의 유일한 모션이 아니다
6. 라벨+`h2`+lead 섹션 헤더가 3회 이하다
7. **같은 AD의 직전 RUN과 골격을 공유하지 않는다** — `node scripts/skel.mjs run-NN-slug --ad AD-1` 로 잰다.
   공유 클래스 5개 이하 · 동일 **골격 규칙** 10% 이하 · 섹션 컴포넌트 재사용 금지.
   **줄 단위로 세면 규격 보일러플레이트가 잡혀 규격을 지킬수록 걸린다** — `skel.mjs` 가 그걸 뺀다. RUN33은 §3.5를 눈으로 보고
   팔레트·주제를 다 갈았는데도 CSS 25%가 같아 오리지널리티 3을 받았다

3번이 리믹스 RUN(짝수)에서 걸리면 **골격은 계승하되 닫는 방식과 꼬리는 새로 짠다.**
계승할 것은 시그니처(팔레트·타입·핵심 인터랙션)이지 모듈 순서가 아니다.
RUN26이 KELVIN 꼬리 3모듈을 통째로 폐기하고도 리믹스로 성립한 것이 그 예다.

### 6. 생성 — **모션은 `animate` 스킬로**
`templates/run-NN-<slug>.html` 자체완결 HTML 한 장. 규격은 `references/spec.md` 참조.
**5단계에서 선언한 시퀀스와 닫는 방식을 그대로 짓는다.** 만들다 바뀌면 5단계로 돌아가 다시 통과시킨다.

모션·인터랙션을 짜기 전에 `animate` 의 **기법 대장**을 대조한다.
IntersectionObserver 리빌은 28/28이 썼고, **슬라이더(`input[type=range]`)는 이미 7번 썼다**
(15·16·17·19·20·21·23). 대장에 이미 있는 것을 또 쓰면 모션 점수가 오르지 않는다.
폴백 4종(로드 · reduced-motion · 900px 이하 · `?capture=1`)도 `animate` 가 들고 있다.

### 7. 자동 검사
```bash
node scripts/verify.mjs run-NN
```
**오류 0이 될 때까지 고친다.** 이건 앞단만 거른다 — 통과했다고 끝이 아니다.

### 8. 브라우저 검증 (건너뛰지 말 것)
지금까지 잡은 결함의 **절반 이상이 여기서만 보였다.**

```bash
python3 -m http.server 5501
node scripts/shoot.mjs run-NN-slug --capture --probe   # 세 폭 오버플로 범인 목록
node scripts/shoot.mjs run-NN-slug --capture           # 세 폭 전체 캡처 → 눈으로 볼 것
```

> ⚠️ **`chrome --headless=new --window-size=390,...` 을 직접 쓰지 마라.**
> 헤드리스 크롬은 **창 최소폭 500px로 클램프**한다. 390을 넘겨도 500에서 렌더한 뒤
> 390으로 잘린 그림이 나오고, 잘린 가장자리가 "가로 오버플로"처럼 보인다.
> RUN30에서 이걸로 없는 결함을 쫓다 시간을 버렸다. `shoot.mjs` 는 CDP의
> `Emulation.setDeviceMetricsOverride` 로 **진짜 뷰포트**를 만든다.

> 🚫 **`--probe` 가 낸 경고가 하나라도 남아 있으면 크리틱에 넘기지 마라.**
> `overflowCount` 만 보고 넘기지 말 것 — **여덟 항목을 전부 읽어라**:
> `overflowBad` · `farFootnotes` · `gridSkew` · **`trackMismatch`** · `foldedCells` ·
> `svgIssues` · `gridFlow` · `rhythmWarn`.
> RUN36 은 `trackMismatch` 가 **901 이상 7개 폭 전부**에서 같은 자리를 지목했는데
> 그 출력을 읽지 않고 출고했고, 크리틱이 그 자리를 데스크톱 구멍으로 잡았다.
> 앞선 세 RUN은 「검사기를 통과했는데 결함이 있었다」였지만 이건 **검사기가 말했는데 안 들은** 것이다.
> 성격이 다르고, 변명의 여지가 없다. 한 줄로 전부 확인한다:
> ```bash
> for w in 390 600 900 1024 1200 1440 1920; do
>   node scripts/shoot.mjs run-NN-slug --w $w --probe --out /private/tmp/pr | tail -40
> done
> ```

- **390 / 1024 / 1440 세 폭**을 직접 본다
- 인터랙션을 실제로 조작해 화면이 바뀌는지 본다
- `?capture=1` 모드가 펼쳐지는지 본다
- 이미지가 `loading="lazy"` 면 강제로 eager로 바꿔 확인한다 (안 그러면 멀쩡한 걸 깨진 걸로 오독한다)

눈으로 보는 검증은 `claude-in-chrome`(실제 크롬 탭)으로,
여러 RUN을 일괄 캡처하거나 같은 검사를 반복할 때는 `playwright`(격리 헤드리스)로 한다.

크리틱에 넘기기 전에 `taste` 의 **자가 대조 6문항**에 스스로 답한다.
하나라도 "아니오"면 고칠 거리가 남은 것이다.

### 9. 독립 크리틱 채점
**만든 주체가 채점하지 않는다.** 자기 작품을 자기가 후하게 보는 걸 막는 것이 핵심이다.
서브에이전트로 띄우거나, 최소한 "근거 없는 칭찬은 감점"을 명시하고 grep·curl로 근거를 잡게 한다.
